## Navigation, billing and checkout workflows

`App.tsx` implements the forward sequence **service confirmation → bill → checkout → payment → history**. The transition to history occurs only after the order is saved successfully.

1. **Select services and open the bill.** `Vreni/src/hooks/useServices.ts` toggles selection by service ID. When `handleConfirmServices` in `App.tsx` receives the selected services, it ignores repeat requests while the bill is opening, stores the selection, and switches to the bill after 500 ms.
2. **Edit and validate the bill.** `Vreni/src/hooks/useBill.ts` recalculates line amounts as unit price × quantity. Decreasing quantity stops at one; removing an item is a separate action. Checkout requires at least one item and a nonblank customer name, but no phone number. `Vreni/src/screens/BillScreen.tsx` guards against repeat checkout requests and, after validation, passes the bill to `onCheckout` after 500 ms. `App.tsx` stores the bill and switches to checkout.
3. **Review and proceed to payment.** `Vreni/src/screens/CheckoutScreen.tsx` shows the customer details, bill items, total quantity, and grand total in rupees. A blank phone number appears as “Not provided.” **Proceed to Payment** calls the supplied callback; the corresponding handler in `App.tsx` switches to payment if a checkout bill exists and otherwise shows an error.
4. **Generate the payment QR.** The QR routine in `Vreni/src/screens/PaymentQrScreen.tsx` rejects missing or nonpositive amounts. It builds an INR `upi://pay` URI with the amount formatted to two decimal places and passes it to `VreniQr.generateQr` with a size argument of `500`. The returned base64 value is stored as a PNG data URI; failures set an error message.
5. **Save the confirmed order.** The confirmation handler in `App.tsx` ignores requests when there is no checkout bill or a save is already in progress. `Vreni/src/hooks/useOrderHistory.ts` rejects empty bills and concurrent saves, then prepends the new order to the stored list. `Vreni/src/storage/storage.ts` writes that list to AsyncStorage. On success, `App.tsx` clears the checkout bill and its selected-service list, switches to history, and shows a success alert. On failure, it shows a retry alert without advancing to history.

**Unavailable paths:** The supplied excerpts do not establish back-navigation destinations, how history is opened from the services screen, how history is rendered, or what UI action invokes payment confirmation. They also do not show the native QR implementation behind `Vreni/src/native/VreniQr.ts`, an external UPI app launch, or transaction verification. The confirmation handler documents an order save, not proof that funds were received.

## Storage, native integration, errors and limitations

### Local persistence

`Vreni/src/storage/storage.ts` uses React Native AsyncStorage to write the full service catalog and order history as JSON arrays under `SERVICES_KEY` and `ORDERS_KEY`, respectively. The supplied excerpts do not show the literal key values or the read implementations, so parsing, validation, and recovery from malformed data are unknown.

- **Services:** `Vreni/src/hooks/useServices.ts` seeds the catalog from `Vreni/src/data/Service.ts` when `getServices()` returns `null`. Price changes and custom services rewrite the catalog and update in-memory state only after the write succeeds. Service selections stay in React state; `Vreni/src/hooks/useLocalStorage.ts` is empty.
- **Orders:** `Vreni/src/hooks/useOrderHistory.ts` reads the existing history, prepends the new order, and writes the full array back. The stored record includes the customer name, phone number field, line items, and total, plus a timestamp-based ID and an ISO creation date (`Vreni/src/types/Order.ts`). The write code does not show application-level encryption.

### Error handling

- `Vreni/src/hooks/useServices.ts` sets error messages for catalog load and write failures. `Vreni/src/screens/ServicesScreen.tsx` alerts when an edited price is not a non-negative safe integer or when the update returns `false`.
- `Vreni/src/hooks/useOrderHistory.ts` logs history read and write failures and clears the corresponding loading or saving flag in `finally`. `saveOrder` returns `false` if a save is already in progress, the bill is empty, or a storage operation fails.
- `Vreni/src/screens/BillScreen.tsx` alerts when it cannot prepare a bill. `App.tsx` alerts when checkout details are missing or the order cannot be saved; the save-failure alert asks the user to try again.
